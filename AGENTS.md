# WordPress plugin

Read README.md. This package owns WordPress UI and isolated workers; reviewed backend services remain in Zoer. Preserve plugin ID, routes, public contract versions and existing data. Do not embed credentials, backup files, account tokens, local checkout paths or operator API access. Use host controls and the scoped request bridge. Keep native imports static and limited to the host allowlist. Scope CSS under `.zoer-native-wordpress-manager`, including modal content.

Run `bun install --frozen-lockfile`, `bun run typecheck`, `bun run test`, `bun run build`, `bun tools/zoer-plugin.mjs validate dist/package`, `bun run release`. Use real Zoer backend state for browser checks. Build/pack output is ignored. Release tags must match the manifest version. Upgrades adding permissions require the existing host review; a UI release cannot install a new host capability. API-types is a public contract snapshot, not a sibling-worktree dependency.

WordPress-side PHP plugins live in `wordpress-plugins/` (Zoer Connect is a submodule of its own public repository; Content Modules is a plain folder); they are not part of the Zoer package. See README "WordPress-side plugins". For editing an existing Zoer-managed DDEV site from outside Zoer, use `.agents/skills/zoer-wordpress-site-edit/SKILL.md`.

Live testing (also from inside a Zoer computer): follow `docs/live-testing.md` and use `tools/live-gate/`. Transfers write only to the DDEV test sites 040-source, 040-destination and 0314; Hilltop Childcare is never touched; other sites are read-only; restore 040-destination to baseline and leave no open approvals. Deploying Zoer is not done from inside Zoer.

Backup restores use the plugin's resumable `backup.restore-local` action and sealed, digest-verified file sets. Hostinger hPanel pairs use the original `.tar.gz` / `.sql.gz` names; never execute uploaded SQL or configuration. Keep the common DDEV administrator preservation, URL replacement and outbound guard. Generated PHP guards must use PHP string literals (`var_export`), because JSON slash escapes change a PHP path. The in-container HTTPS smoke check needs `X-Forwarded-Proto: https`, matching the trusted DDEV bridge; a same-URL 301 without it is not a successful check. Test restores against the real DDEV runtime and read back their catalog receipt.

Scanner packaging uses `security/runtime/` as a reviewed CI fallback without private submodule access. Keep its descriptor sourceCommit identical to the scanner gitlink and its exact bytes/digest consistent with `scripts/security-runtime.ts`. Initialized scanner source is rebuilt and compared byte for byte; do not bypass a mismatch or auto-fetch upstream tooling. CI initializes only the public Zoer Connect submodule.

# WordPress Manager 0.12.2

Publishes the Push to live, Pull and Transfers review pass and the transfer
fixes found while pushing a real site to live.

**Push to live**

- *Everything* compares by SHA-256 by default and selects the database with
  the files that differ; files the live site already has are not uploaded. The
  dialog says how many identical files are left out, warns if the database is
  cleared, and keeps **Push every file anyway**. *Everything* states that live
  user accounts are kept and that core and must-use plugins are not pushed.
- While a transfer (such as a refresh) holds the local site, the dialog shows
  it and waits instead of reporting an inventory error.
- Visible choice for *Code only* / *Everything*; the default exclusions always
  apply and the box adds patterns; the confirm field keeps what was typed;
  Local/Live tags; the destination's history; the test-passed note only after
  a successful test.
- The push worker reads a comparison five pages at a time and splits batches
  Zoer refuses as too large (sites of several thousand files failed with
  "Record lookup too large").

**Pull from &lt;site&gt; and Transfers**

- One *User accounts* group with refresh-specific wording; no duplicate
  "Database only"; selected style on the Into list; saved settings below the
  options.
- "Nothing running now." replaces the wrong "No transfers of this site yet";
  the separate *Local copies* button is gone (a download's *Make a local copy*
  opens "Local copy from a download"); older complete or files downloads that
  a newer verified one supersedes fold away (database-only downloads, which may
  be backups, never fold); panel summaries no longer repeat their title.

**Locks and local exports**

- A local export releases earlier bridge stagings of the site itself, in its
  own slice: only exports younger than the bridge's 24-hour job lifetime,
  newest first, including abandoned unfinished ones (the run holds the site's
  transfer lock). A purged job counts as released; the first refusal ends the
  releases because it can spend the runtime ticket.
- `wpcli.read` locks only itself (`readId`, group `site-read`): reads neither
  wait for the site's transfers nor refuse one another. **This changes the
  action's resumable lock and needs the host's capability review; until it is
  accepted (Extensions → Enable), Zoer keeps WordPress Manager disabled.**

Existing site IDs, connections, catalogs and transfer receipts are preserved.
No Zoer host or DDEV bridge update is required beyond the 0.12.1 requirements.

Release validation: frozen dependency install, type check, tests, production
build, manifest/package validation and deterministic release packaging. The
same code ran on the live Zoer as development builds: a guided *Everything*
push of a 6,252-file site uploaded the database and 10 changed files (3.15 MB
of 137 MB), passed review, Finish and the public-site check, and a later test
push on the reviewed build compared all files as identical. WordPress-site
transfers and core/extension changes require their usual separate review;
publishing this package does not perform them.

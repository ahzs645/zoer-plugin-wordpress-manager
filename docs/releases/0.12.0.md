# WordPress Manager 0.12.0 (development)

## Stack file (`zoer-wordpress.json`)

See [the stack manifest proposal](../proposals/site-stack-manifest.md) for the format.

- A site's **Development** tab has a **Stack file** section. It describes the site's plugins and
  themes by where they come from, using WordPress Playground's source names:
  `wordpress.org/plugins` / `wordpress.org/themes` (optionally an exact version), `url` (a ZIP
  with its required `sha256`) and `git:directory` (an HTTPS Git URL without credentials, with an
  optional ref and folder). Zoer Connect is never part of a stack file.
- **Export** downloads the stack file or a Playground blueprint, or saves `zoer-wordpress.json`
  into a Repos repository. Saving uses a narrow host route that can only write that one file, so
  it needs no new permission.
- **Apply** loads a stack file from a repository, a GitHub link or a paste, shows what is already
  installed and what is missing, then installs and activates what is missing. A ZIP is checked
  against its SHA-256 before it is unpacked; a repository plugin or theme is installed without
  changing the site's development link, with rollback.
- What an apply actually installed (commit, version, digest) is kept separately as a
  `stack:<siteId>` record, the way Composer keeps a lock file, because the stack file itself
  states intent only.

## Site Editor changes for themes

- For a block theme developed from a repository, **Site Editor changes** lists the copies the
  Site Editor saved in the database (templates, template parts and global styles).
- **Save to theme** writes them into the repository's theme files for review, with undo, like
  Create Block Theme's *Save Changes to Theme*.
- **Remove Site Editor copies** is offered only when the theme files already show the same
  content, and keeps what it removed so it can be restored.

## Push to live

- **Push to live** warns when a code-only push would leave Site Editor edits behind on the local
  site, and when the live site's own Site Editor copies would hide the pushed theme files. The
  live check uses Zoer Connect 0.7.0's read-only `/theme-overrides` (names and dates only); an
  older connector shows no live warning.

## Requirements and permissions

- Zoer host with repository Git metadata, stack-file save, versioned wordpress.org and
  SHA-256-checked ZIP installs, repository installs and theme capture (Zoer branch
  `feat/wordpress-stack-and-theme-capture`), and the DDEV bridge / page proxy forwarding the key
  for `/theme-overrides`.
- Zoer Connect 0.7.0 on a live site for the live Site Editor warning.
- Upgrade review: the `theme-overrides` endpoint (`GET`, read) and the `themeOverrides` input of
  `site.test`.

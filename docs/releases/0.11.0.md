# WordPress Manager 0.11.0 (development)

## A clear local ⇄ live pathway

- A site's **Overview** starts with **Local and live**. On a local copy it shows the live site
  it came from with **Push to live** and **Pull from live**; on a live site it lists its local
  copies (Pull / Push to live each) and **Make a local copy**.
- **Push to live** is one dialog: source → live site (preselected for a local copy, chosen
  otherwise), the live site's readiness (Push allowed, Imports set up, Private storage, each with
  its fix and a link to WordPress → Tools → Zoer Connect), then *What to push* (**Code only**,
  recommended, or **Everything**), **1. Export**, **2. Compare with the live site**, (3. Options),
  **Push**, followed by the push's review/Finish card. The newest export is selected
  automatically, including one that finishes while the dialog is open. It replaces "Publish
  local changes → Continue to Push → the destination's full Transfers dialog".
- **Pull from live** opens the existing local-copy refresh with this copy already selected.
- **Transfer & publish** on a local site leads with Push to live; the Hostinger account
  publication is labelled as such below it. The site menu says **Push to live**.
- The live site's **Transfers** dialog shows four readiness chips (Pull, Push, Imports, Storage)
  instead of twenty capability badges, which moved under *Connection details*. A Push blocked by
  unfinished destination setup now says *Finish “Destination import setup”*, not *Update Zoer
  Connect*. Descriptions and dry-run text are one sentence each.

## Public verification and cache clearing

See [public-verification.md](../public-verification.md).

- New action `publication.verify` checks what anonymous visitors receive after a publication and
  keeps "transfer completed", "purge requested/accepted" and "current publicly" separate:
  **Published · check pending**, **Current on checked pages**, **Old content detected**,
  **Check failed**, **Not verifiable**. It runs after Finish, on **Recheck**, and with a bounded
  backoff after **Clear caches and recheck**.
- New action `publication.purge` asks Zoer Connect to clear WordPress caches (approval always).
  The hosting cache uses the existing Hostinger site tool for an explicitly linked Hostinger
  website; the CDN is reported as requested, never as confirmed.
- An expired Hostinger authorization shows a banner with **Reconnect** on the site page; the
  account list says *Not checked recently* instead of a lasting "Connected".

## Requirements and permissions

- Zoer host with the `endpoint-public` network scope (`publicProbe`) and the DDEV bridge / page
  proxy forwarding the key for `/publication` and `/cache/purge` (Zoer branch
  `feat/wordpress-public-verification`).
- Zoer Connect 0.6.0 on a site for anything but "Not verifiable".
- Upgrade review: `endpoint:site:…:public`, `network:response-bytes:4194304`,
  `resumable:publication.verify`, actions `publication.verify` and `publication.purge`. The
  plugin's bundled CLI (`tools/zoer-plugin.mjs`) was re-exported from that Zoer so `validate`
  knows `publicProbe`.

# WordPress Manager 0.10.1

This stable release adds repository-backed WordPress plugin development. Clone/import in Repos, then select the repository in WordPress Manager to prepare tools, build assets and install reviewed saved code on a local DDEV site or local copy. After installation or replacement, open development from that installed plugin's entry.

- Native PHP/Composer setup, automatic saved-file builds, nested npm inspection and staging.
- **Link site** and existing-plugin replacement, preserving activation.
- Reviewed source/destination digests, PHP syntax checks, current-build gating and private code rollback.
- Plugin-specific development with the existing site/folder fixed, linked-source display and filtering of conflicting repository links.
- Shared repository/computer/build host services reusable by other Zoer plugins; Repos remains the general source and Git interface.

The matching Zoer host changes are required. This package adds `workspace:repositories`; upgrades from older stable releases require normal permission review. Existing WordPress site links, settings, transfer records and recovery history are preserved. Production publishing remains a separate reviewed workflow. See [the full workflow](../repository-development.md).

## Install or update

In Zoer's **Plugins** interface, select the **GitHub release** source with repository `ahzs645/zoer-plugin-wordpress-manager` and tag `v0.10.1` (or latest). Stage the package, review its upgrade/permissions and enable it after applying. The release includes `wordpress-manager-0.10.1.zip` and `zoer-plugin.json`, which Zoer verifies before installation.

Once installed from the GitHub release channel, **Check for updates** follows this repository's stable releases. A local development or manually uploaded package does not automatically follow GitHub: select the GitHub release once to move onto that channel. Stable 0.10.1 sorts above 0.10.1-dev builds.

Release validation: typecheck, 285 package tests, build, manifest validation and release packaging; the preceding development qualification covers actual saved edits/build-on-save, active-plugin replacement, preview and code rollback on the dedicated CampusManager site. Physical iPhone/WebKit and arm64 tool bootstrap remain unqualified.

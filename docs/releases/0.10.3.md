# WordPress Manager 0.10.3

Code-only publishing now supports selecting plugins without selecting a theme, and selecting themes without selecting a plugin. Previously an unchecked resource retained an empty “Selected” mode and failed shared export validation before an archive was created. Disabled resources now carry a neutral selection while their resource flags remain false. Enabled resources still require specific choices.

No permissions or host contracts change. Database, media, login settings, must-use plugins and server configuration remain excluded by the code-only preset. The reviewed file comparison and activation steps remain required.

Update through Zoer’s Plugins interface using the GitHub release source `ahzs645/zoer-plugin-wordpress-manager`, tag `v0.10.3` or latest. Stage, review, apply and enable the package. Existing GitHub-channel installations can use **Check for updates**. Do not replace an active development package while another chat is testing unpublished changes.

Validation: plugin-only and theme-only preset tests run through the same worker export validator; excluded folders remain blocked, and enabled empty selections still fail. Typecheck, complete tests, build, package validation and release packaging are required before tagging. The observed Intramurals transfer used the explicit export controls as a workaround, then the protected code-only comparison and activation flow; it does not count as end-to-end validation of the corrected preset on an installed release.
